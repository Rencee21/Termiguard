# Termiguard (Flutter)

A Flutter/Dart mobile app for early termite activity detection by
**listening**. The photo-upload step and the heatmap/geomapping have
been removed; the app now follows this flow:

1. **Connect Hardware** — check the ESP32, microphone and power supply.
2. **Scan** — listen to the sensor's audio for a fixed period, with live
   level bars, a timer and a progress bar.
3. **Spectrogram** — see the recorded audio as frequency over time, with
   the 3–5 kHz termite band outlined and a count of "band hits".
4. **History Result** — detection result and confidence, the spectrogram
   again, and a saved scan history you can re-open.

| Step | Flutter screen | Notes |
|---|---|---|
| Home | `HomeScreen` | Landing page + "How Termiguard Works" |
| 1. Connect Hardware | `HardwareScreen` | Simulated async device-connection check |
| 2. Scan | `ScanningScreen` | Collects audio frames; live spectrum bars |
| 3. Spectrogram | `SpectrogramScreen` | Full spectrogram + band-hit read-out |
| 4. Result | `ResultsScreen` | Result, spectrogram, summary, Save Result |
| History | `HistoryScreen` | On-device persistence via `shared_preferences`; each entry shows a spectrogram thumbnail |

## Real ESP32 data (via Firebase)

The app never talks to the ESP32 directly; the ESP32 writes to Firebase
Realtime Database and the app reads it (`lib/services/esp32_service.dart`):

- `termite_detector/detector01/status` - `lastUpdate` is the heartbeat.
  **Connect Hardware** shows Connected only while it keeps updating.
- `termite_detector/detector01/events/<id>` - one entry per detected click
  (`peakDb`, `peakFreqHz`). **Scan** collects the clicks that arrive during
  the scan and draws them on the spectrogram. The result is worked out from
  that recording. The scan stops by itself if the hardware goes offline.

Frequency settings live at the top of `lib/models/spectrogram_data.dart`:

```dart
const double kMaxHz = 8000;      // top of the spectrogram
const double kBandLowHz = 3000;  // termite band, lower edge
const double kBandHighHz = 5000; // termite band, upper edge
const double kHitThreshold = 0.5; // band energy that counts as a "hit"
```

## Android setup (included, current-Flutter-compatible)

The `android/` folder is included and uses the **current Flutter Gradle
template**: Kotlin DSL build files, Android Gradle Plugin 8.11.1, Kotlin
2.2.20, Gradle 8.14.5 (the versions recent Flutter releases require — if
`flutter run` still complains that Gradle is too old, check
`android/gradle/wrapper/gradle-wrapper.properties` and bump it further,
since Flutter's minimum creeps up with new releases). Crucially,
`compileSdk` / `minSdk` / `targetSdk`
are all set from `flutter.*` (e.g. `minSdk = flutter.minSdkVersion`)
instead of a hardcoded old number — this is what avoids the
*"flutter doesn't support the oldest Android version"* error, since
those values are always resolved from whatever Flutter SDK you build
with, not baked in.

**One manual step is required:** this sandbox has no network access,
so the small `gradle-wrapper.jar` binary (normally auto-generated by
`flutter create`) isn't included — everything else in `android/` is
real and ready. To add it, do either of:

- Open the project in Android Studio and let it sync (it fetches the
  wrapper jar automatically), **or**
- Run this once from the `android/` folder, if you have Gradle
  installed: `gradle wrapper --gradle-version 8.10.2`

After that:

```bash
flutter pub get
flutter run
```

If you'd rather skip that step entirely, deleting the `android/`
folder and running `flutter create .` will regenerate it (including
the wrapper jar) from your local Flutter SDK — it will still pick up
the current, non-hardcoded SDK versions the same way.

## iOS setup

The `ios/` platform folder isn't included (Xcode project files are
binary/plist-heavy and must come from Xcode tooling). Generate it with
`flutter create .` on a Mac with Xcode installed. No camera or photo
library permissions are needed any more. (When you connect a real
microphone/ESP32 over Bluetooth or Wi-Fi you may need to add the
matching usage descriptions.)

## Notes

- Minimum Flutter SDK: 3.27+ (Dart 3.3+), Material 3 (the project already used APIs from 3.27, such as `CardThemeData`).
- Dependencies: `shared_preferences`, `intl` (`image_picker` was removed
  along with photo upload, along with the camera/storage permissions in
  `AndroidManifest.xml`).
- Scans saved by the earlier photo/heatmap version still load; they just
  have no spectrogram.
- No backend/API calls are made; all data is generated on-device or
  stored locally.
